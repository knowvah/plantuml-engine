## Objective

Core ships only the themes MIT allows. The others stay available through two packages that the user's code registers.
- Core (`src/core/themes-source.ts`) keeps 35 themes: the 31 MIT ones, `mars`/`toy`/`vibrant` (Apache-2.0, with the
  licence text in `dist/licenses/`), and `_none_` (D7).
- `@knowvah/plantuml-themes-unlicensed` gets amiga, blueprint, crt-amber, crt-green, mimeograph, plain, mono and
  carbon-gray. `@knowvah/plantuml-themes-gpl` gets sunlust (D6).
- `themeStore(...packages)` and `withThemes(includeStore, store)` register them (D1). An unregistered moved theme gives
  upstream's `Cannot load theme <name>` (D2).
- With both registered, every render is byte-identical to today.

## Stop conditions (halt, journal, report)

1. A rendered SVG changes with both packages registered, whether an expected SVG moves, a ratchet pin moves, or
   `before.sha256` ≠ `after.sha256`, and you cannot state the mechanism with `file:line`.
2. A conformant row would be lost, or `--accept-rises` looks necessary.
3. The same gate fails on 2 consecutive fix attempts.
4. A finding contradicts D1 to D7: amend `decisions.md` with the date, then halt.
5. A licence fact differs from the ruling: a header, an author, or the future-architect repo now holding a `NOTICE`.
   That is the maintainer's call (CLAUDE.md, divergences).
6. Anything would write `~/git/plantuml`, push, publish to npm, or change `oracle/accepted-divergences.json`.

A file outside a task's write-set is **not** a stop: change it and journal why (CLAUDE.md, "Writing and write-sets").
