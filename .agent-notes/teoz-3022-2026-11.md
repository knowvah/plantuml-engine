# teoz #3022 port (upstream cf9e4d42a)

## Observation: a note over several never takes part in the `&` disjoint push
- **Context**: porting `PlayingSpace#cannotPushApart` (PlayingSpace.java:294-311).
- **Finding**: `noteTileFootprint` (src/diagrams/sequence/sequence-note-width.ts) returns `undefined` for an `OVER_SEVERAL` member, because `NoteTile#getX` is `RealUtils.middle(posC1, posC2)` (NoteTile.java:200-203) and no `Anchor` spells a middle. So `parallelDisjoint` emits no constraint when either side is such a note, whatever `cannotPushApart` says. The jar does push where `cannotPushApart` is false: `note over A, B : y` + `& note left of C : a rather long note text here` puts C at lifeline x 253.481 in the jar (b066ee08c) and 196.756 here, and shifts A to 129.638 (jar 21.681). This predates cf9e4d42a (the old jar pushed every over-several pair).
- **Impact**: the cf9e4d42a fixtures match only because both sides skip the push; any `&` pair with a note over several on the left and a tile starting right of its rightmost participant still diverges until a middle anchor is modelled in `sequence-real-force.ts`.
- **Confidence**: High (jar render and ours compared with `compareSvg`).
